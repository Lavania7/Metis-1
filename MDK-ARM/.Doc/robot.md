## Develop 开发
在系统复杂度低的时候，开发只是写代码
但在复杂度高的系统里，在开发时，需要预先想好正在“写的代码”属于以下内容的哪一项：

- **Template 模板：稳定，不随项目变化**
    驱动框架（CAN / UART / PWM）：一般是Bsp层的内容
    基础数据结构（电机、遥控器、机构）：一般是Drv，Device层的内容
    调度框架：一般是在app,sys层预先声明，并在底层放置好的主要函数，或其他各层的init函数，如main.c或stm32xxx_it.c中的函数
    通用工具（滤波、限幅、数学库）：一般是Lib层的内容
- **Interface 接口：稳定，开发功能时的基本规则**
    数据结构的“使用权限”（谁能写，谁只能读）
    数据流方向（单向 or 双向）
    更新时机（周期 / 事件）
    精度与单位（避免隐性错误）
- **Function 功能：习惯意义上的“写代码”**
    控制算法（PID / 前馈 / 状态机）
    模式逻辑（遥控 / 自动 / 安全）
    任务编排（动作序列）
- **User 用户交互：提供给非开发者的修改事项**
    遥控器映射
    UI / 上位机控制
    参数调节接口
- **Debug 调试：这些内容调试时需要读写**
    上位机通信
    日志缓冲区
    实时变量监控
    断点或者其他形式的检查点

一般而言，好的开发顺序是“自下而上提需求，自上而下写代码”
